# C 的恢复与版本关系回归

## 自动化

在仓库根目录运行：

```powershell
node --test docs/prototypes/c-practice/tests/model.test.mjs docs/prototypes/c-practice/tests/app.test.mjs
```

本轮使用 Node.js 24.18.0，无第三方测试依赖。模型测试直接运行生产模块；控制器测试给浏览器 I/O 提供可控替身并运行生产 app.js。后者不等于浏览器测试；恢复页、下载和用户流程另在 Edge 实操。

覆盖三种规则、可达草稿阶段、同方案保持、不同方案 v2、重复操作、v1 不变、方案/观察/反思 ID、未知或重复材料、伪造结果、断裂关联、错误字段、版本不兼容、数字时间戳、空 v1、存储失败、并发更新、清除失败和用户输入转义。

## 浏览器夹具

必须使用独立端口，避免影响 8765 的已有草稿。在仓库根目录启动：

```powershell
py -3 -m http.server 8766 --bind 127.0.0.1 --directory docs/prototypes/c-practice
```

代码修改后确认浏览器加载最新文件。静态服务器秒级 Last-Modified 及浏览器缓存可能保留旧脚本；可使用禁用缓存的本地测试服务器并重新进入。本轮未因此修改生产资源或服务策略。

### 坏存档

1. 打开 http://127.0.0.1:8766/tests/fixtures.html，写入只在此隔离地址启用。
2. 载入非法 JSON、错误字段、不兼容 schema、空记录、数字时间戳或两版存档空 v1，写入并打开演练。
3. 核对恢复提示，导出原草稿副本并与输入逐字节比较。刷新后不能静默替换。
4. 取消清除应保留原数据；确认清除应回到新交接簿，刷新后可继续。

### 仅本页暂存的重置冲突

1. 打开 http://127.0.0.1:8766/tests/faults.html，建立草稿并载入应用。
2. 点击模拟应用保存失败，在下方应用编辑目标，确认“仅本页暂存”。
3. 点击另一页面写入新草稿，再在下方应用确认重新开始。
4. 核对结果应为 PASS，应用显示另一页面更新提示。

测试框架读取真实入口的页面结构并运行真实 app.js，仅在框架内注入存储写入异常，不改变浏览器设置、不调用服务、不触碰 8765；离开即结束注入。它只验证保存边界，不作为生产 CSP 验证。

### 选回原方案并填写有效理由

从空白选 K1+S3，填写目标，预览增配替班、打开维护、完成反思并选择修改一次安排。在第二版页选回增配替班，先核对空理由拦截，再填写有效保持理由。刷新应恢复草稿；记录理由、导出成果并刷新。

预期：只有原 v1、一个维护观察和一条 keep 反思；v1 内容和 ID 不变；反思的 basedOnPlanRecordId/resultPlanRecordId 都指向 v1；新保持理由存入 response，维护缺口仍保留。

## 修复与边界

| 问题 | 修复前 | 修复后 |
| --- | --- | --- |
| 仅本页暂存时重置 | 绕过磁盘版本检查，可能删除其他页面的新草稿 | 重置前总是比较当前磁盘版本，冲突时锁定并要求重读 |
| 时间戳类型 | Date.parse 接受某些数字并强制转换为日期 | createdAt 必须为可解析字符串 |
| 两版记录的空 v1 | 遍历 ID 时显示内部 TypeError | 遍历前校验对象，显示统一完整性错误 |

保留坏存档供备份，不执行自动迁移、自动补齐或静默清除。旧的有效 schema 1 存档仍可读取。

真实模块联调、课程 PDF 原文、完整读屏/Tab 审计、整个浏览器进程重启及实体手机仍需独立验收。集成差异见 [INTEGRATION.md](INTEGRATION.md)。
