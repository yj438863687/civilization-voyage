# 历史岛屿：技术与文明

主线围绕技术怎样改变共同生活：水利与储粮、动力与劳动、通信与发声、人工智能与责任。每条航线只追问一个问题，玩家在具体处境里安排资源，再看到决定带来的后果。

四段航程保留农业时代、工业时代、信息时代、人工智能时代；每段分为**内海 · 中国**与**外海 · 世界**。时代名称用于组织议题，各航线按自己的历史年代前进，不表示全球同时进入同一阶段。

## 八条年代链

下表依次列出两座岛屿、一次危机和终点回顾。传说中的排序数值只用于叙事先后，不是可靠纪年。

| 时代 / 航线 | 标题 | 两岛 → 危机 → 回顾者 |
| --- | --- | --- |
| 农业 / 中国 | 水流向谁的田 | 鲧的传说「堤外还有人」→ 禹的传说「一条渠，两岸田」→ 约前 256 年都江堰背景「春汛前的一次商量」→ 战国的李冰 |
| 农业 / 世界 | 粮仓里的名字 | 约前 3500 年「把收成留下来」→ 约前 3200 年「泥板记得谁」→ 约前 3200 年「欠收后的仓门」→ 虚构的乌鲁克老书记员 |
| 工业 / 中国 | 从一本书到一条路 | 1839—1841 年「先把世界读清楚」→ 1842 年「书该送到哪里」→ 1909 年京张铁路背景「路通之前」→ 詹天佑 |
| 工业 / 世界 | 机器转起来以后 | 1769 年「省下来的煤」→ 1833 年「钟声下的童年」→ 1842 年「交货日的工班表」→ 虚构的工厂调查员 |
| 信息 / 中国 | 电线接上之后 | 1871 年「海缆来到岸边」→ 1881 年「津沪之间的两封信」→ 1896 年办学背景「谁来守下一班」→ 盛宣怀 |
| 信息 / 世界 | 连通不等于听见 | 1844 年「四十英里之外」→ 1866 年「大洋两边的等待」→ 1948 年「有限的信道」→ 克劳德·香农 |
| 人工智能 / 中国 | 把什么交给机器 | 2017 年「一张更快的调度表」→ 2021 年「多问一句同不同意」→ 2035 年未来推演「没有被算进来的港口」→ 虚构的轮值船长 |
| 人工智能 / 世界 | 会回答，能负责吗 | 1950 年图灵问题 / 1966 年 ELIZA「像在理解你」→ 2016 年「棋盘上的一手」→ 2016 年「演示厅外的决定」→ 虚构的机器智能展策展人 |

回顾者必须处于能讨论本程事件的年代。历史人物的回顾台词均为创作；未来船长、书记员、调查员和策展人明确标为虚构。图灵的少年照片只作历史回望，不把他设为 2016 年事件的见证者。

## 连续故事、十二种操作与实际后果

每条路线用一件可以传递的物件连接三章：分水图、仓单、工坊笔记、工厂改造记录、报房值班册、求助信、自动调度规程、实验札记。`storyArcs.ts` 给出每章要解决的问题与下一章的接续。跨年代的人物与物件接力明确为创作，不宣称它们是已经发现的史料。

故事内先亲手完成技术操作，留下可复查的结果，再决定怎样使用这项能力：

| 操作 | 实际规则 | 接力与议题 |
| --- | --- | --- |
| 连渠试水 | 转动渠段，水必须沿互通的口进入两块田 | 第二章继承旧渠图再修弯口；通水与轮灌规矩分开 |
| 装仓拼放 | 在16格仓位放置不同形状的物资，检查越界与重叠 | 后来可沿用仓位图；种子、余粮与谁能开仓 |
| 译稿、排字与校样 | 重排五项流程后试印，错序不会自动修正 | 从认得零件到交给工匠，再走向施工 |
| 勘线与铺设 | 相邻格铺线，避开险地；村庄支线另需工料 | 前章技术成果提高额度；短线与沿途使用机会 |
| 锅炉控压 | 加煤、做功、泄压，记录过压与耗煤 | 前章疲劳减少可用燃料；交货与检修余量 |
| 工班调度 | 4人×6时段，检查覆盖与连续工作疲劳 | 疲劳确实进入后章资源，不只改变文案 |
| 拍发电码 | 逐拍输入短点、长划，按字母校验 | 完整送出的内容与随后安排的发送次序分别记录 |
| 噪声纠错 | 对三份受损副本逐位做多数恢复 | 实际核对可靠性与占用容量的代价 |
| 数据授权 | 勾选任务必要资料，额外个人资料不增加任务能力 | 额外暴露影响人心，并成为后章复核的一项材料 |
| 规则对话实验 | 对情绪、事实和矛盾分别提问，按实际响应分支计数 | 不调用外部模型，不把关键词重叠算作多次实验 |
| 围棋提子 | 五路教学棋局检查气与提子，禁止自杀落子 | 不复现比赛、不运行AlphaGo；棋盘证据不代替航海验证 |
| 方案复核 | 对计算、过期资料、矛盾前提作不同处理 | 读取前章数据或棋局记录，加入具体复核材料 |

`challenges.ts` 保存规则，`VoyageChallenges.tsx` 负责实际操作。每章产生 `quality`、`summary`、`plan`、`strain`，与使用技术的安排一起由 `challengeOutcomes.ts` 结算；只在确认决定并回到船上时应用一次。

较可靠的操作可省回3份补给，部分成果省回1份，未完成的操作需要2份修补成本；疲劳、遗漏或额外暴露会影响人心。合作仍有后章省料回响，但不再是唯一的承接。失败可以继续故事，记录会保留未完成之处。终点的 `arcEnding` 依实际技术与安排选择最后一页，不能无条件宣布共同守护成功。

## 船坞与换装

首页有“船坞与换装”预览入口；航行中可按B打开并暂停船。使用与海上相同的船体、船员模型及参数，可旋转、缩放、切换船员近景，另有键盘可用的转向、缩放与还原按钮。未解锁外观也能先预览，预览不扣资源。首页在确认航程前只作预览，避免新开局重置资源时抹掉刚购买的整修；启航后可整修和换装。

补给用于修整舷板、添置航灯、挂起船队旗，分别花费18、26、34份，每次至少留下15份口粮。人心达到55、65、75时解锁常服、行装与共同船徽，换装不消耗人心。外观跨时代保留；新开局仍遵循原先从起点出发的规则。

## 史料、创作与图片

`apps/web/src/world/history.ts` 中每站的 `source` 保存背景来源标题与链接，阅读页直接显示。来源覆盖古籍、博物馆、工程遗产、档案、法律与规划、研究机构资料；背景来源不证明互动人物、选择或台词真实发生过。

内容性质通过 `nature` 区分「史实背景」「古代传说」「未来推演」，界面同时说明互动人物、对话与选择为创作。鲧禹没有可靠纪年；2035 年港口是未来情境创作；古代欠收、施工排班和试航等抉择是创作，不能当作事件复原、人物原话或技术预测。

图片从本地 `apps/web/public/history/` 提供。展示元数据及实际图注见 `apps/web/src/world/historyMedia.json`，逐图作者、来源与原许可另见 `apps/web/public/history/ATTRIBUTION.json`；阅读页可展开「图片来源与授权」。图片已缩放并转换为 JPEG，分别保留原许可，不能统一套用项目代码许可。

图注说明图片真正表现的对象和年代差异：现代都江堰照片用于理解分水结构；约前 2350 年吉尔苏泥板晚于乌鲁克故事；20 世纪电键不是 1871 年上海设备；1918 年詹天佑照片晚于铁路通车；围棋棋盘不是 AlphaGo 赛场；天河二号照片不是未来港口。配图包含画像、版画、器物和设施照片，不宣称是互动场景的实拍。

## 阅读界面与扩展

沿用 [墨海铜灯](ART_DIRECTION.md) 的墨、铜、纸与朱砂主操作。桌面以摊开的阅读页呈现：左页图像和来源，右页年代、故事与操作；700px 及以下改为上下堆叠。保留清楚的正文行距、键盘焦点、可滚动面板与减少动态设置，不用新视觉系统替代航海身份。

扩展时以 `history.ts` 的 `HISTORY_ROUTES` 为航线故事的单一数据源，填写问题、两岛、危机、终点、背景来源和内容性质；相关世界入口、遭遇与回顾应引用这里的数据，避免复制另一套标题和年代。媒体键指向 `historyMedia.json`，添加本地文件并同步 `ATTRIBUTION.json`，如实说明年代、地点和表现对象的差异。

新增或调整年代后运行 `node scripts/test-history.mjs`。现有检查约束岛屿到危机的 `order` 不倒流、终点不早于危机，并检查区域、遭遇入口、图像文件和来源、前站回响及升级边界。新增航线时同步检查中的数量约束；传说排序不能改写成史实纪年。界面交互验证入口为 `apps/web/tests/history.html` 与 `apps/web/tests/history.tsx`。这里记录验证入口，不代表本次文档修改已执行这些检查。

## 小游戏的操作反馈

每种玩法在操作区直接给出目标和三步指引，额外提示中说明何时可记录、哪些情况属于未完成。流程是读故事、动手试验、作出安排、最后写入航程；试验完成度与共同生活的选择分开。记录试验后将焦点移到结果，避免停在已经禁用的棋盘上。顶部固定当前步骤与返回按钮，Escape也能退出；未写入航程的操作不结算，已完成章节保留。

`world/challengeSound.ts`用本地Web Audio合成机关、装仓、金属铺轨、蒸汽、拍发、落子与印记声。`ChallengeFeedback.tsx`在实际操作处理函数中接收同一事件，用音频时钟安排播放起点，并把同一延时和时长交给画面。电报码短点90毫秒、长划270毫秒，拍发时锁定下一拍，防止叠音。锅炉压力针对应实际压力，飞轮只在做功时转，泄压才显示蒸汽；渠水只沿接通的格子显示。

首次手动操作后启用声音，音量和静音保存在本机；新操作替换上一段短反馈，离开故事、静音或切到后台会停止声音。系统要求减少动态时保留颜色、压力、连接结果和文字，取消空间运动。声音不可用时，仍能通过画面与文字完成操作。

`scripts/test-challenge-feedback-browser.mjs`验证实际音频图产生非零波形，比较拍发动画与音频起点，检查90/270毫秒时长、快速连拍、静音记忆、卸载停声、机件和水流、手机布局与减少动态模式。

## 海上故事入口

`world/storyAccess.ts` 是可见锚点与登岛范围的唯一规则。历史岛用岛屿偏移后的中心，第三章用村落偏移后的图片中心；罗盘、接近判定和入口按钮必须用同一个位置。范围覆盖船头接近岸边的距离，随船长变化，不要求船中心进入岛内。只有当前航道的岛可交互或阻挡航行。

靠近后可按E、点屏幕入口或点图片。第二章、第三章按前章完成情况开放，未开放时在入口直接写出原因。港口图片可点击，也可按F靠岸回顾。已完成的故事保留重读、练习入口，可随时结束重读或按Escape返回；练习不发奖励，也不覆盖原选择。旧记录中已收入日志的材料也算完成，避免刷新或旧存档与前端状态不一致而被锁住。

`node scripts/test-story-entries-browser.mjs` 使用真实App与3D海域检查全部24个操作入口、8个港口总结、顺序提示和重读；它通过独立API（默认8015）创建测试航程，测试地址由 `VOYAGE_TEST_URL` 指定。几何规则另在 `test-history.mjs` 中检查全部16座岛四侧范围和第三章偏移，不能用直接渲染小游戏组件代替海上入口验证。


## 船型、配乐与故事现场

船体升级保留原有3级存档字段、18/26/34份补给消耗与15份口粮底线。每级现在增加可见的舱体、甲板与设备，按时代形成四阶段船型：农业的有仓粮船、双帆与双体船；工业的封闭货舱、双烟囱与高桥；信息时代的报务舱、碟形天线与通信甲板；人工智能时代的值守舱、双体与观测设备。改造位于既有航行轮廓内，不改变靠岸范围。所有造型均为游戏概念设计。船坞支持初始船型对照，预览不扣费。

`world/voyageMusic.ts`以原创音符谱合成四段持续配乐，各有旋律、和声、低音与时代音色。浏览器在首次指针或键盘操作后起奏；切换时代换曲，进入故事降低音量，操作音效触发时进一步压低并恢复。配乐与操作音效独立控制，偏好保存在本机，后台暂停。首页、海上、故事与船坞都可打开配乐控制。

24章的`StoryTheatre`各有三处现场与人物可查看，补充该章里技术能力和共同生活的矛盾。小游戏通过结构化操作事件传递真实进度，现场田地、仓位、列车、机件、报文或数据连接随之改变；决定阶段使用实际补给、人心结果显示物资去向，不额外结算或发放奖励。配图仍保留原来源，现场与人物话语明确为创作。

装仓、排字与铺线支持鼠标、触控及点按。装仓显示可放置/冲突的占格；排字支持插入和重排；铺线可按住连续绘制。动作仍调用原有规则与结算，拖拽不是另一套计算。

`node scripts/test-immersion-browser.mjs`覆盖真实配乐波形、四曲切换与控制、四时代四阶段船型及像素差异、24章三处现场、拖拽与场景联动。可加`--interaction`只运行拖拽及联动检查。
