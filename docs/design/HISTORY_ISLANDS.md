# 历史岛屿：技术与文明

主线围绕技术怎样改变共同生活：水利与储粮、动力与劳动、通信与发声、人工智能与责任。每条航线只追问一个问题，玩家在具体处境里安排资源，再看到决定带来的后果。

四段航程保留农业时代、工业时代、信息时代、人工智能时代；每段分为**内海 · 中国**与**外海 · 世界**。时代名称用于组织议题，各航线按自己的历史年代前进，不表示全球同时进入同一阶段。

## 八条年代链

下表依次列出两座岛屿、一次危机和终点回顾。传说中的排序数值只用于叙事先后，不是可靠纪年。

| 时代 / 航线 | 标题 | 两岛 → 危机 → 回顾者 |
| --- | --- | --- |
| 农业 / 中国 | 水流向谁的田 | 鲧的传说「堤外还有人」→ 禹的传说「一条渠，两岸田」→ 约前 256 年都江堰背景「春汛前的一次商量」→ 战国的李冰 |
| 农业 / 世界 | 粮仓里的名字 | 约前 3500 年「把收成留下来」→ 约前 3200 年「泥板记得谁」→ 约前 3200 年「欠收后的仓门」→ 虚构的乌鲁克老书记员 |
| 工业 / 中国 | 从一本书到一条路 | 1839—1841 年「先把世界读清楚」→ 1842 年「书该送到哪里」→ 1909 年京张铁路背景「路通之前」→ 詹天佑 |
| 工业 / 世界 | 机器转起来以后 | 1769 年「省下来的煤」→ 1833 年「钟声下的童年」→ 1842 年「交货日的工班表」→ 虚构的工厂调查员 |
| 信息 / 中国 | 电线接上之后 | 1871 年「海缆来到岸边」→ 1881 年「津沪之间的两封信」→ 1896 年办学背景「谁来守下一班」→ 盛宣怀 |
| 信息 / 世界 | 连通不等于听见 | 1844 年「四十英里之外」→ 1866 年「大洋两边的等待」→ 1948 年「有限的信道」→ 克劳德·香农 |
| 人工智能 / 中国 | 把什么交给机器 | 2017 年「一张更快的调度表」→ 2021 年「多问一句同不同意」→ 2035 年未来推演「没有被算进来的港口」→ 虚构的轮值船长 |
| 人工智能 / 世界 | 会回答，能负责吗 | 1950 年图灵问题 / 1966 年 ELIZA「像在理解你」→ 2016 年「棋盘上的一手」→ 2016 年「演示厅外的决定」→ 虚构的机器智能展策展人 |

回顾者必须处于能讨论本程事件的年代。历史人物的回顾台词均为创作；未来船长、书记员、调查员和策展人明确标为虚构。图灵的少年照片只作历史回望，不把他设为 2016 年事件的见证者。

## 故事内的四种机制

每站遵循「读背景 → 进入故事操作 → 看后果 → 记入航程」，小游戏嵌在故事里，并共用补给、人心与航程记录。

| 机制 | 操作与提交条件 |
| --- | --- |
| 分配物资 `allocation` | 在两种用途之间改派八份物资或时辰；至少四份进入第二用途时采用相应安排。 |
| 安排工班 `workshop` | 改派四班，至少两班用于休息、培训或复核时采用相应安排。 |
| 接发消息 `dispatch` | 四封中先发两封；可选两封商单、两封急用消息，或一封商单加一封急用消息。混合选择单独记下已发与仍等待的消息。 |
| 核对材料 `review` | 点开全部材料，再从两种安排中决定；读完材料不替玩家作决定。 |

前站选择会在后站复述。前站采用合作安排时，下一站结算省回 3 份补给；混合发报保留自身结果。终点沿年代链回顾三次决定，不只展示抽象分数。操作前显示补给、人心变化及剩余补给；无法承担的安排不能提交。

补给用于整修船体：修整舷板、添置航灯、挂起船队旗分别花费 18、26、34 份，每次至少留下 15 份口粮。人心达到 55、65、75 时依次解锁常服、行装、共同船徽；换装不消耗人心。

## 史料、创作与图片

`apps/web/src/world/history.ts` 中每站的 `source` 保存背景来源标题与链接，阅读页直接显示。来源覆盖古籍、博物馆、工程遗产、档案、法律与规划、研究机构资料；背景来源不证明互动人物、选择或台词真实发生过。

内容性质通过 `nature` 区分「史实背景」「古代传说」「未来推演」，界面同时说明互动人物、对话与选择为创作。鲧禹没有可靠纪年；2035 年港口是未来情境创作；古代欠收、施工排班和试航等抉择是创作，不能当作事件复原、人物原话或技术预测。

图片从本地 `apps/web/public/history/` 提供。展示元数据及实际图注见 `apps/web/src/world/historyMedia.json`，逐图作者、来源与原许可另见 `apps/web/public/history/ATTRIBUTION.json`；阅读页可展开「图片来源与授权」。图片已缩放并转换为 JPEG，分别保留原许可，不能统一套用项目代码许可。

图注说明图片真正表现的对象和年代差异：现代都江堰照片用于理解分水结构；约前 2350 年吉尔苏泥板晚于乌鲁克故事；20 世纪电键不是 1871 年上海设备；1918 年詹天佑照片晚于铁路通车；围棋棋盘不是 AlphaGo 赛场；天河二号照片不是未来港口。配图包含画像、版画、器物和设施照片，不宣称是互动场景的实拍。

## 阅读界面与扩展

沿用 [墨海铜灯](ART_DIRECTION.md) 的墨、铜、纸与朱砂主操作。桌面以摊开的阅读页呈现：左页图像和来源，右页年代、故事与操作；700px 及以下改为上下堆叠。保留清楚的正文行距、键盘焦点、可滚动面板与减少动态设置，不用新视觉系统替代航海身份。

扩展时以 `history.ts` 的 `HISTORY_ROUTES` 为航线故事的单一数据源，填写问题、两岛、危机、终点、背景来源和内容性质；相关世界入口、遭遇与回顾应引用这里的数据，避免复制另一套标题和年代。媒体键指向 `historyMedia.json`，添加本地文件并同步 `ATTRIBUTION.json`，如实说明年代、地点和表现对象的差异。

新增或调整年代后运行 `node scripts/test-history.mjs`。现有检查约束岛屿到危机的 `order` 不倒流、终点不早于危机，并检查区域、遭遇入口、图像文件和来源、前站回响及升级边界。新增航线时同步检查中的数量约束；传说排序不能改写成史实纪年。界面交互验证入口为 `apps/web/tests/history.html` 与 `apps/web/tests/history.tsx`。这里记录验证入口，不代表本次文档修改已执行这些检查。
