# 审美方向：墨海铜灯

> 状态：视觉负责人提案，供小组讨论。设计变量见 [tokens.css](tokens.css)，组件规范见 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)。

## 一句话

夜里的一间海图室：舱外是深墨色的海，舱内一盏铜灯照着摊开的海图和日志。用户坐在海图桌前，和船员讨论去哪，在图上落印确定航线，然后推开舱门出海。

## 为什么选这个方向

| 需要 | 做法 |
| --- | --- |
| 有游戏空间感，不像管理后台 | 主界面是一个有纵深的 3D 船舱，面板是舱内的实物（海图、日志、通讯台），不是网页卡片 |
| 能装载古风、现代、未来不同场景 | 船舱和海图桌是“中性容器”，用墨、纸、铜这些跨时代材质；文明的视觉只出现在舷窗外和登陆后的场景里 |
| 让用户看清任务、资源与进展 | 夜色背景压低环境，信息放在纸面和铜刻度上，对比清楚；一屏只有一处被灯光照亮的焦点 |
| 区分史实、推演、创作和测试 | 用“印章”体系统一标记内容性质，颜色加文字加形状三重区分 |
| 模型与 API 配置不抢主叙事 | 收进舱内“通讯台”抽屉，只在航线页和需要时出现 |

## 不做的事

- 不堆发光边框、半透明毛玻璃卡片、装饰性仪表盘。面板是不透明的纸或舱壁，HUD 底板用纯色半透明，不做模糊。
- 不用霓虹色和大面积渐变做“高级感”。高光只给一处焦点对象（`--cv-shadow-lamp`）。
- 没有授权素材时，不画具体的真实遗址、历史建筑或文物。用剪影、体块、海图符号代替，并标注“概念示意”。
- 不用模型品牌色和 Logo 代表船员身份。船员身份由职务和席位纹样表示，模型只是可配置属性。
- 概念图只用于讨论方向，不作为最终界面，也不作为史实依据。

## 色彩

三类基础材质加一个场景色：

- **墨海**（`--cv-ink-*`）：舱壁、夜海、底层表面，占画面 60–70%。
- **纸**（`--cv-paper-*`）：海图、日志、文化材料。凡是“内容本身”都放在纸上，便于长时间阅读。
- **铜**（`--cv-brass-*`）：可操作的仪器、刻度、次要按钮、等待用户选择的状态。
- **朱砂**（`--cv-cinnabar-*`）：用户的印。只用于“由用户做出决定”的主操作（确认航程、启航、提交成果）和失败状态。一屏最多一个朱砂主按钮。
- **场景色**（`--cv-scene-accent`）：由当前文明场景提供，只用于舷窗外环境、港口标记和场景内的点缀，不进入通用控件。

## 字体

- 标题：思源宋体 / Noto Serif SC。有书卷感，适配古今。
- 正文与界面：思源黑体 / Noto Sans SC。
- 数字、用量、坐标、时间：IBM Plex Mono，等宽数字，便于对比预算和实际用量。
- 场景可通过 `--cv-scene-display-font` 为场景内标题换字体，但通用界面不变。

## 材质与光照

| 对象 | 材质 | 光照 |
| --- | --- | --- |
| 船舱 | 深色木与涂漆金属的中性混合，低细节 | 一盏暖色主灯（2700K 左右）+ 舷窗透入的场景光 |
| 海图桌 | 纸面，带细网格和等深线 | 主灯直射，最亮区域 |
| 仪器 | 拉丝铜，刻度线清晰，无霓虹 | 边缘轻微高光 |
| 海面 | 低多边形加法线贴图，颜色由 `--cv-scene-water` 决定 | 场景主光 + 雾 |
| 天空 | 两色渐变（`--cv-scene-sky-top` → `--cv-scene-sky-horizon`） | 不做体积云，首版用雾控制远景 |
| 测试海域 | 灰色网格海面，无文明元素 | 中性白光 |

## 空间层次

从远到近五层，界面元素只出现在后三层：

1. **远景**：天空、雾、远处岛屿剪影（场景提供）。
2. **中景**：海面、船、港口体块（场景提供，3D）。
3. **世界标签**：港口名、碎片位置，随 3D 投影，可被遮挡。
4. **HUD**：四角固定，只显示当前任务、资源、航向和少量操作。
5. **面板与抽屉**：对话、海图、日志、通讯台。打开时 3D 降低亮度但不暂停（减少动态模式下暂停）。

## 通用船外形：宝船气势

用户每次出海看到的是同一艘船。它的气质来自明初宝船与福船：**宽体、高艉楼、多桅硬帆**。这艘船是产品的标志物，它是否“够霸气”直接决定启航页的第一印象。

**声明（必须随任何概念图与素材一起标注）**：这是**概念设计，不是考古复原**。不针对、不冒充任何一艘历史上的具体船只，也不是某一艘沉船或档案记载船只的还原。宝船的原始尺度本身在学界有争议（《明史》所载“长四十四丈四尺”等数字存疑），因此下面给的是**视觉比例，不是历史尺寸**。不使用未获授权的出土文物纹样、器物照片或他人复原图上的装饰细节。

### 外形要点

以总长 L 为基准：

| 部位 | 做法 |
| --- | --- |
| 船体 | 宽体，长宽比约 4:1；方形平艉、前端上翘，侧面为外张弧线；不做欧式尖艏 |
| 艉楼 | 占船长后 1/4，**三层**，逐层后退成阶梯，最高层带栏杆与挑檐。轮廓比任何部位都醒目——“霸气”主要来自这里 |
| 艏楼 | 占前 1/10，一层，低矮，给艏部一点厚度，不与艉楼争主体 |
| 帆 | 硬帆（横杆帆），6–8 桅；主桅居中偏前，甲板以上高度约为 2.5 倍船宽；横杆间距均匀，帆面有折线，可分层收帆 |
| 舵 | 船尾中央的大舵，舵杆与舵叶可见；不加西式船首像 |
| 船眼 | 艏部两侧各一只，白底墨瞳，略高于水线；气势与“生命感”的来源之一，不发光 |
| 栏杆与走道 | 沿舷与各楼层的连续木栏杆，给船增加层次与尺度感 |
| 隔舱节奏 | 侧面横向木分隔线，约每 1/12 L 一道，只作造型节奏，不宣称复原了隔舱数量 |

### 材质与色彩

墨木船体 + 朱漆楼层与栏杆 + 铜金配件（灯具、护角、舵首饰条）+ 米色硬帆 + 场景旗帜。

船上的朱漆与界面上“朱砂主操作”色值相近但用途完全不同：**船上的朱漆永远是材质，界面里的朱砂永远是“用户落印”**。3D 里不允许用朱漆色做可交互高亮。

船体颜色走 `--cv-ship-*` 变量（见 [tokens.css](tokens.css)），不散写在材质文件里。

### 比例建议（给 3D）

**L : B : 桅高 ≈ 4 : 1 : 2.5**（桅高指甲板以上主桅高度）。

若 L = 100 单位：

| 项 | 值 |
| --- | --- |
| 最大船宽 B | 25 |
| 主桅甲板以上高度 | 62.5 |
| 吃水 | 9–10 |
| 干舷（甲板到水线） | 8 |
| 艉楼 | 后 25，三层，每层高 5，共 15 |
| 艏楼 | 前 10，高 4 |
| 桅数 | 6–8，硬帆 3–5 面为主视觉 |

按 1:1 单位建模后整体缩放；不要按真实米数建模（会引出无法核实的“复原尺寸”主张）。

### 镜头

| 场合 | 机位 |
| --- | --- |
| 启航 | 四分之三侧影（正面偏前 20–30°），略俯 8–12°，距离约 1.8L；**整船入画，艉楼完整不被裁切**，后方是天空与雾 |
| 航行 | 斜后上方：方位角 30–40°，俯角 15–20°，距离 1.2–1.5L；船占画面宽约 1/3，前方留出目的地海面 |
| 靠港 / 进入场景 | 从航行机位推近到侧面或斜前方，船头朝向港口 |
| 减少动态 | 直接切到对应机位；不做环绕、不做推镜 |

不环绕船体、不低角度仰拍船底、不穿过帆与桅杆。

### 船是通用容器

换场景只换：`--cv-ship-banner`（默认取 `--cv-scene-accent`）、旗帜图案、帆上的点缀色，以及舷窗透进的场景光。

**船体结构、长宽比、楼高、桅数、船眼位置不变。** 允许的皮肤差异只有：帆色、旗帜、木色深浅一档。不允许为了让某个场景“更酷”而加装炮门、改尖艏、加西式船首像或改变比例。

### 夜港灯光圣经

参考 [concepts/boot-night-harbor.jpg](concepts/boot-night-harbor.jpg)（概念设计，非考古复原）：墨色海、月光冷轮廓、艉楼灯笼暖光、水线雾、水面碎光。整页只有三处亮源，其他都靠环境光托出。

#### 光源表

| # | 光 | 类型 | 色 | 强度 | 位置 | 作用 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 主光 · 月光 | DirectionalLight | `--cv-ship-lamp-cool`（#8fb6c8） | 0.55 | 左后上方，az −140°，el 42° | 勾船体、帆、艉楼挑檐的冷轮廓；不产生强阴影 |
| 2 | 辅光 · 舱口/灯笼 | PointLight × 3 | `--cv-ship-lamp-warm`（#f0b46a） | 各 1.6，衰减距离 1.2L | 艉楼三层各一盏，居中偏内 | 照亮朱漆楼层、栏杆、窗棂；这是画面最暖的一块 |
| 3 | 环境 | HemisphereLight | 上 `--cv-scene-sky-horizon`，下 `--cv-scene-water` | 0.35 | 无限远 | 托住暗部，不让船底死黑 |
| 4 | 水线反射 | 无实体灯 | 场景水色 × 1.35 | — | 船侧水线 | 由水 shader 的反射项生成，见交接清单 |

补充：
- 帆不受灯笼暖光直射（距离远），只吃月光与冷环境，因此帆比艉楼暗、比海面亮，形成三联层次：**暖艉楼 > 冷帆 > 暗海**。
- 船眼不发光，只靠材质高光和一点月光侧照，不参与 emissive。
- 甲板灯串（如有）是纯 emissive 小球，不参与照明计算，避免灯数爆炸。

#### 舷灯与灯笼的 emissive

| 项 | 值 |
| --- | --- |
| 灯笼本体 | emissive `--cv-ship-lamp-warm`，强度 1.0；内部核心小球 `--cv-ship-lamp-core`，强度 2.0，半径约 0.012L |
| 灯笼外轮廓 | 不描边、不加光晕贴片；靠曝光与色差区分 |
| 舷灯（船侧一排） | emissive `--cv-ship-lamp-core`，强度 0.8，半径 0.008L，数量以此前的圆窗节奏为准 |
| 光晕 | 只有主灯（艉楼最高层）允许一张 0.15L 的软 Sprite，不透明度 0.35，无动画 |
| 禁止 | 不做呼吸/闪烁、不做全船泛光、不给船眼加光晕 |

#### 水色与水线雾

| 项 | 值 |
| --- | --- |
| 近水色 | `--cv-scene-water` 提亮 15%，夜港以墨绿青为主（图 1 的 #1d3a38 一带） |
| 远水色 | `--cv-scene-fog` 向天空方向插值，水平线处完全融合 |
| 水线雾 | 高度 0.05L 的软雾带，颜色取 `--cv-scene-fog`，不透明度 0.35；船体入水处加密，形成“船从雾里出来”的观感 |
| 雾平面 | 一个 Y 轴贴地的雾面 + 一张半高雾墙，不用体积雾（首版成本高） |
| 水面碎光 | 只在亮源正下方（灯笼与月亮）生成竖向拉长的反射条，长度 0.3–0.8L，抖动幅度 0.004L |
| 镜面 | 见交接 §2.3：反射用一次平面反射或屏幕空间近似二选一，先给低成本版 |

#### 艉楼挑檐（用体块做，不做宫殿）

三层递退的体块 + 每层檐下一条薄挑檐，**不做完整歇山顶、不做斗拱、不做彩画**。

| 层 | 体块 | 挑檐 | 顶部 |
| --- | --- | --- | --- |
| 一层 | 长方体，占宽 0.22B，高 0.20L | 四面挑出 0.02L，厚 0.012L，端部上翘 8° | — |
| 二层 | 缩进 0.04B，高 0.18L | 挑出 0.018L，厚 0.010L | — |
| 三层 | 缩进 0.04B，高 0.16L | 挑出 0.016L，厚 0.010L | 四坡缓顶，坡度 18°，只在四角抬起 10° |

- 挑檐用薄板 + 一条铜色檐口线（`--cv-ship-trim`），不要雕花。
- 屋檐四角上翘靠顶点的轻微位移实现，不做飞檐斗拱。
- 轮廓识别靠**三层的阶梯退让 + 挑檐的水平线**，剪影在纯黑下也能认出是楼船。
- 最高层可有 1–3 个铜色脊饰，几何体（球 + 锥）即可，**不复制文物脊饰造型**。
- 窗棂：发光小矩形网格，5×8 以内，纯 emissive，不做实际几何窗格。

#### 禁止项

- 霓虹色、青色发光边框、赛博朋克配色。
- Bloom 滥用：全屏 Bloom 只允许一次后处理，阈值高到只吃灯笼核心与月亮；不做整船泛光、不做彩虹色差。
- 西式船首像、炮门、桅顶风帆旗式样、尖艏。
- 把艉楼做成宫殿或塔：不超过三层，不用完整屋顶、斗拱、彩画、匾额文字。
- 船眼发光，或把船眼做成可交互高亮。
- 用朱漆色做界面状态色或 3D 交互高亮（朱漆是材质）。
- 用未授权的文物纹样、他人复原图的雕饰。

## 驾驶舱体块（概念，素材待补）

驾驶舱是船体内部的一个舱室：一间前侧开的甲板室，位于主甲板上、艉楼之前。素材未到时全部用体块搭，用来验证尺度与镜头；素材到了只换材质与细节，**尺寸与相机锚点不变**。

### 坐标与尺度

- 船局部坐标：y-up，**船头朝 −z**，+x 右舷，−x 左舷，原点在船中水线。
- `L = 100`：船头 z = −50，船尾 z = +50，主甲板 y = 8，桅顶 y = 70.5，艉楼顶 y = 23。
- 舱内层高 9.3（0.093L），比真实舱室高，为镜头视野与可读性服务。这是**风格化比例，不是复原尺寸**。

### 舱室

| 项 | 值 |
| --- | --- |
| 占地 | x ∈ [−8, +8]（宽 16），z ∈ [+2, +22]（深 20），位于艉楼（z ≥ 25）之前 |
| 地面 | y = 8.2；天花 y = 17.5；壁厚 0.6 |
| 天花 | 平顶 + 两道横梁（0.8 × 0.8），位于 z = +7 与 z = +17，不做拱顶 |

### 开口

| 开口 | 位置 | 尺寸 |
| --- | --- | --- |
| 前窗 | 前壁 z = 2.3 | 洞 x ∈ [−4.5, 4.5]，y ∈ [9.8, 14.3]；**两根竖棂（宽 0.5）在 x = ±1.5 处**，分成三扇 |
| 左舷窗 | x = −8.3 | z ∈ [7.5, 12.5]，y ∈ [10.2, 14.2]，单扇 |
| 右舷窗 | x = +8.3 | 同上 |
| 舱门 | 左舷壁 x = −8.3 | z ∈ [12.8, 15.2]（宽 2.4），y ∈ [8.2, 13.7] |

窗下沿 y = 9.8，比桌面（9.25）高 0.55 —— **坐下后视线不会被桌面挡住，也不被窗台切断**。

相机在座位 `(0, 11.9, 16)` 沿 −z 看：视线在窗平面（z = 2.3）的高度约 11.65，落在洞口内；窗外的可见范围是船头甲板、低矮的艏楼与海平线。

### 舱内光照

| 灯 | 参数 |
| --- | --- |
| 桌上灯 | `PointLight`，(0, 12.4, 8)，色 `--cv-ship-lamp-warm`，强度 1.2，衰减距离 25；灯体为锥台 + 球形罩，罩内小球 emissive `--cv-ship-lamp-core` 强度 2.0 |

舱壁上每 2 单位一道浅缝，不做护墙板雕饰。

### 素材未到时

- 全部用长方体与圆柱体拼装，纯色 + 上述变量，不留黑块占位。
- 窗框、铜条、门框用细长体块，保证窗与门在剪影上可识别。
- 完成后挂「素材待补」小签，与测试港口同一套样式。

## 文明内核如何被看见

> 【AI推荐待确认｜推演/创作】本节是视觉负责人对 Codex 文化内核（分支 `docs/cultural-kernel` 的 `docs/culture/`）的审美诠释，供组员审议。概念定义、出处与边界以 [KERNEL.md](../culture/KERNEL.md) 为准；这里只回答“玩家看见什么、手上做什么”。不是课件要求照画，不是传统图像学定论。主核 / 辅核仍待 Maya 与组员确认。

### 总原则：内核是一种光照与手势，不是一行字

【AI推荐待确认｜推演；出处：CHI1293 作业1 / W3–4 p09 / W1–2 / W5–6 p04–06、p11】主核建议为**知行合一**，辅核为**和而不同、仁义**；玄览玄通仍是驾驶舱的起点。这些词**不出现在 HUD、按钮、加载页、帆面、旗帜和启航标题上**。它们在画面里只有三种存在方式：

1. **光落在哪里**——一屏只照亮一处等待判断的东西（沿用 `--cv-shadow-lamp` 单屏一处）。
2. **手做了什么**——落印、把材料带到港口、修订理由，这些动作才是内核本身。
3. **什么被允许留下**——分歧、疑点、未被听见的人、旧的理由，都不会被画面擦掉。

审美上的检验句：**关掉所有文字说明，只看光、动作和留下的痕迹，玩家仍能感到“我在负责地判断”。** 做不到这一点的设计，加再多古字也不算承接了内核。

### 墨海铜灯如何承接玄览、仁、义

【AI推荐待确认｜创作/推演；概念出处：CHI1293 W1–2（修身）/ W3–4 p06–10、p15 / W5–6 p02–06；玄览为既有产品命名】

| 材质 | 承接 | 画面里怎么做 | 不要画成 |
| --- | --- | --- | --- |
| **墨**（夜海、暗舱） | **玄览 · 澄明**：先把杂念压暗，一个问题才能被看清 | 墨不是神秘，是“收拢”。驾驶舱进入时其他面板压暗，只剩任务卡在灯下；玩家写下问题之前，海图桌上只有空白纸面和网格，不预先摆满答案 | 玄学迷雾、满屏书法、“开悟”光效；用暗降低正文对比度 |
| **铜灯**（桌上那一盏） | **仁 · 恻隐的光**：灯照得见眼前人，也照得出灯圈之外还有人 | 灯是有边界的暖圈。灯圈之外不是“没有”，是“还没照到”：海图上未被询问的人以未上色的铅笔点留在纸边，玩家打开相关材料时灯圈移过去，铅笔点被描成墨。**灯只会移动，不会变成全场照明** | 圣人光环、神谕按钮、给某个船员或模型更亮的“正确光”、悲情特写逼选 |
| **铜线 + 墨线**（海图上的航线） | **义 · 当走的路**：在利与责之间画出一条可解释的路 | 航线由玩家落印后才由铅笔改墨；墨线旁的铜刻度写的不是“收益”，而是这条路**查了什么、暂不查什么**。港口安排的后果以墨线分支标出“谁受益 / 谁承担”，两支同粗 | 红绿道德路线、“正义之路”金光、把较贵路线画得更华丽 |
| **朱砂**（只有一处） | **信 · 责任主体** | 见下文印章体系：朱砂只属于玩家的手 | 把朱砂用于装饰、警告色或模型自动确认 |

光照数值不变：舱内仍是**一盏暖色桌灯 + 窗外冷光**（见「驾驶舱体块 · 舱内光照」），不为“仁”额外加灯。仁的表达靠灯**移动到哪里**，不靠灯**多亮**。

### 涟漪：从自己到他人到天下（以及后来者）

【AI推荐待确认｜推演/创作；出处：CHI1293 W5–6 p09–13（差序格局、涟漪、宇宙的空间/时间责任）/ W1–2（修身→天下）】涟漪在本产品里是**空间层次**，不是一圈扩散动画。从近到远五层，与已有的“远景→面板”五层空间叠合：

| 圈 | 谁 | 空间位置（船局部 / 世界，`L` = 船长） | 光与雾 | 玩家能做什么 |
| --- | --- | --- | --- | --- |
| 己 | 玩家与自己的问题 | 海图桌、灯圈（0–0.1L） | 唯一暖光，最亮 | 写问题、写理由、落印 |
| 同船 | 船员两声部 | 船员席、舱内（0.1–0.5L） | 同一盏灯的余光，两席亮度相同 | 听、追问、不采纳 |
| 他人 | 港口里与安排直接相关的人 | 目的港，**1.5–3L**，在雾近端以内 | 港口灯清楚，暖点可数 | 用材料做安排，看谁受益 |
| 未被看见者 | 安排影响到、但画面原本没有的人（隐去的劳动、翻译、中介、无声者） | 港口之后的**远灯，4–7L**，位于雾中段 | 小而暗的暖点，无标签 | 材料提到他们时，远灯被标出名字（“尚未听见：码头工人”），可点开材料 |
| 后来者 | 尚未出生、不能发言的人 | 海平线，**≥ 8.5L**，雾完全融合处 | 无灯，只有尾迹与海平线 | 在日志里回答“后来的人还能改这份安排吗？”（C 场景最强） |

规则：

- **雾只作用于 3D 世界，不作用于信息。** 远处的人在 3D 里暗，但他们的材料卡与近处材料**同纸、同字号、同对比度**。距离只表示“容易被忽略”，**不表示价值更低**。
- 远灯没有“点亮进度”。被标出名字的远灯不会变得比港口更亮，也不计数；它只是从无名变成有名。
- 现有雾参数（海面 shader `uFogNear 55 / uFogFar 170`，`SHIP_L = 20`，即约 2.75L / 8.5L）恰好对应“他人在雾内、未被看见者在雾中、后来者在雾尽头”，**不需要改雾，只需在 4–7L 放远灯**。
- 不做扩圈动画宣告“涟漪已达天下”。课程透镜提醒关怀随距离变薄；画面只负责让距离**可见**，不负责宣布它已被克服。

### 印章体系：既是控件，也是“信”的视觉

【AI推荐待确认｜推演；出处：CHI1293 W3–4 p10、p15（AI 能格物，致知在人；认识谦逊）/ W1–2（信）/ 作业2 p02】印章在这里同时承担两件事：标出**内容性质**，以及记录**谁负责**。核心立场：**流畅不等于真，落印不等于真。**

三层印，物理上分开、颜色上不混：

| 层 | 谁盖 | 视觉 | 在哪 |
| --- | --- | --- | --- |
| **性质印**：史实 / 推演 / 创作 / 测试 | 内容编辑与材料自身（不是模型、不是玩家） | 印在材料纸角，海 / 铜 / 紫 / 石板色，实线边 + 前缀字（见 DESIGN_SYSTEM） | 每段材料、每条船员引用 |
| **审议印**：AI推荐待确认、待核实 | 编辑状态 | 琥珀**虚线**边；“待核实”加问号角标 | 候选场景、未核材料 |
| **采纳印** | **只有玩家** | 朱砂实印，唯一的朱砂；印面写“采纳”+ 当时的疑点数（“采纳 · 疑点 2”） | 任务卡、解释、港口安排、日志 |

作为控件：

- **落印是按住，不是点击。** 按住约 0.6 秒，印从纸上方落下（MOTION A 类“落印”），中途松手即取消。这一下停顿就是“我愿为此负责”的手感；减少动态时为按住时长内的进度环，不省略按住。
- **没有理由不能落印。** 理由栏为空时印章是空心描边、不可按，旁边写“写下理由，由你落印”。
- **采纳印不会改写性质印。** 玩家采纳一段【推演】后，它仍是【推演】，旁边多一枚朱砂“采纳”，二者并列；绝不出现“采纳后变史实”或金色对勾。
- **印面略有不匀**（墨色边缘 2–3% 噪声、轻微旋转 ±2°），是人手留下的痕迹；模型输出永远没有这种痕迹，只有可观察事件。
- **流畅≠真的视觉**：船员发言放在舱壁面板（墨底），材料放在纸上。再流畅的发言也不会出现在纸上，除非它引用了一份材料，此时纸上显示的是**那份材料**及其性质印，而不是船员的话。
- **“分歧”不是红色。** 本轮将 `--cv-mark-dissent` 从朱砂改为纸色双线（见 tokens.css）。分歧不是错误，也不是玩家的印；朱砂只留给玩家的决定与失败。

### 和而不同：差异共存，不是对立进度条

【AI推荐待确认｜推演/创作；出处：CHI1293 W1–2（和合、好汤）/ W5–6 p11 / W3–4 p08–09】

- **船员双声部**：大副（求证）与二副（义利提醒）坐在同一张海图桌两侧，席位同大、同亮、同材质；职务以席位纹样区分（大副为等深线纹，二副为航迹点纹），不用品牌色。两人同时有话时**左右并排**，各自保留出处条；用纸色双线“分歧”印连接，而不是合成一条。界面里**永远不出现**比分、票数、左右拉锯条、谁占多少百分比。
- **同意与不同意可以同时成立**：一条发言可以带两个小标签——“同意去查”“暂不同意此解释”。这是和而不同最小的可见单位。
- **航线深浅**：两条航线画在海图上的不同水深。较简单路线走浅水（等深线稀、颜色浅），步骤较多路线走深水（等深线密）。**两条线同粗同墨**；深只表示“查得更多”，不表示“更对”。选中那条由灯照亮，未选那条保留铅笔线，不消失——没走的路也被记住。
- **好汤是构成关系，不是汤碗图标**：任务卡上“共同任务”与“保留的分歧”同字号、同位置权重，分歧不被折叠成“更多”；港口里不同群体的灯保持各自的形状（圆、方、长）并排在码头，不统一成一种灯，也不调成同一颜色。
- 不做：把差异混成同一颜色、拼成异域装饰盘、凡事取平均的“折中”按钮。

### 知行合一：收集不是完成

【AI推荐待确认｜推演；出处：CHI1293 W3–4 p07–10、p13–15 / 作业2 p02】

- **货舱里的碎片是“未用”的纸条。** 收入货舱时纸条是铅笔色、略卷边，角上写“未用”；只有当它在港口被引用来说明一项安排后，才变成墨色平整、角上写“用在：<安排名>”。
- **没有收集计数。** 不显示“3/5 碎片”、不显示收集进度条、不做图鉴墙。HUD 资源区只有两本账，不放碎片数。
- **港口灯由行动点亮，不由靠岸点亮。** 靠港时码头灯是原本的样子；玩家用材料做出一项安排并落印后，安排涉及的那几盏灯才在海图上被描进日志。
- **行之后要能回看**：安排落印后，海图上出现两支同粗墨线“谁受益 / 谁承担”，并给出“要改一处吗？”的修订入口；修订后旧理由以划线保留，不被覆盖。
- 3D 重现对象的“线框 → 体块 → 材质”三阶段（SCREEN_SPEC §6）只绑定**玩家的行动步骤**，不绑定收集数量。

### 生生：海与航程不断生成，不是通关

【AI推荐待确认｜推演/创作；出处：CHI1293 W1–2（生生）/ W5–6 p13】

- **没有终局画面。** 反思页最后一项不是奖杯或“文明重现完成”，而是“带上没解决的问题，再走一程”；按下后镜头从日志抬起回到舷窗，海仍在流动。
- **海图是可叠写的纸。** 每次航程的航线以墨留在海图上，下一次航程的新线画在旧线之上，旧线淡到 30%。海图越用越有“人走过”的层次，但**永远不会被画满**，也不做“全图点亮”。
- **海面永不静止**（减少动态时除外），尾迹在身后淡出：走过的路会被海收回，留下的只是日志里的理由。
- 不做：“每秒自动增产”、资源永动的数字、地图雾 100% 揭开的成就。

### 只可被“做到”、不可被“画成大字”的概念

【AI推荐待确认｜推演；出处：KERNEL.md 各条“不可游戏化”】下列概念**不作为上屏标题、按钮名、HUD 标签、帆面字、旗帜字、加载页标语、成就名**。它们只能通过上面的光、手势与痕迹被体验；名称只出现在“关于本作 / 课程出处”说明页与日志的出处段，并附课程出处。

| 概念 | 只能这样被做到 | 绝不这样被画出 |
| --- | --- | --- |
| 知行合一 | 材料被用于安排，看后果，修订 | “知行合一”四个大字、书本连到船舵的图标、集齐图鉴 |
| 仁 | 灯移到原本没照到的人；远灯被标出名字 | 爱心计数、仁字纹样、悲情特写 |
| 义 | 写清收益归谁、代价谁担，再落印 | 正义值、红绿道德路线 |
| 信 | 按住落印、疑点随印保留、更正留痕 | 诚信勋章、金色认证对勾、“已验证”光效 |
| 和而不同 | 双声部并排、分歧双线、未选路线保留 | 拉锯条、投票比分、“和”字 Logo |
| 玄览 / 澄明 | 驾驶舱压暗只剩一处灯下的问题 | 开悟光效、神秘雾、“玄览模式”按钮 |
| 致知在人 | 采纳印只由玩家盖 | “人类负责”四字横幅、模型自动盖印 |
| 天下 / 大同 | 远灯、后来者的问题在日志里被询问 | 全图占领、扩圈动画宣布大同 |
| 生生 | 海图叠写、再走一程 | 自动增产、通关结算 |

**可以写成字的**：产品名“文明航程”、功能名（驾驶舱、海图、海域、日志、通讯台）、具体动作（落印、靠港、收入货舱、修订）、具体问题（“这件事，会影响谁？”）。语气与可上屏短句见 [CULTURAL_VOICE.md](CULTURAL_VOICE.md)。

### 30 秒内被感到（验收用的最短路径）

【AI推荐待确认｜创作】一个没上过课的人，从启航到第一次落印，应依次**感到**而不是读到：

1. **0–5 秒**：夜港里一艘灯亮着的船——“有人在这里认真做事”（墨 + 一盏灯）。
2. **5–15 秒**：推进舱内，四周压暗，只有桌上一张空纸被照亮，问“你想弄清什么？”——注意力被收拢（玄览）。
3. **15–25 秒**：写下问题后，两位船员同时开口，一个问“哪处能查证”，一个问“这会影响谁”；两人并排，没有比分（和而不同 + 仁义）。
4. **25–30 秒**：确认航程的印是空心的，必须先写一句理由，再按住，朱砂落下，印面写着“疑点 1”——这是我的决定，它没有假装已经正确（信 + 致知在人）。

如果走查时玩家需要读一段说明才明白以上任何一点，说明设计失败，应回到光、动作和痕迹去改，而不是加字。
